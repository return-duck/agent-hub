# 节点输入输出技术设计

本文依据 [需求文档](需求文档.md)。它说明数据怎么存、运行时怎么求值、以及要改哪些现有文件。本文不包含那些改动。

## 现状

节点能力的真源是 [contracts/node-manifest.json](../contracts/node-manifest.json)。`npm run codegen` 把它写进 `frontend/src/generated` 和 `node/src/generated`。

| 节点 | 现在的配置 | 现在的输出 |
|---|---|---|
| `start` | `inputVariables` 列表，类型可以是 string / number / boolean | 每个变量一个端口，路径 `input.<name>` |
| `prompt` | `template` 绑定，角色 system / human | 字段 `text`，写入 `scratchpad.prompt` |
| `llm` | `system`、`temperature`、`tools`、`maxSteps` | 字段 `text`，有文本时写入 `scratchpad.answer` |
| `http` | URL、请求头、请求体都是绑定 | `status` / `ok` / `body` / `json` / `result` |
| `code` | 代码 `source`，输入是 `bindingList` 或旧的 `name=path` 行 | 单个 `result`，类型由 `outputType` 决定 |
| `end` | 一个 `value` 绑定；空则在没有模型消息时用 `scratchpad[outputKey]` | 无出参表 |

前端：

- 调色板把清单里的节点全部列出来：[frontend/src/components/AgentSidebar.tsx](../frontend/src/components/AgentSidebar.tsx) 的 `manifest.nodeTypes.map`。
- 配置表单按 `uiSchema.widget` 渲染：[frontend/src/components/Inspector.tsx](../frontend/src/components/Inspector.tsx)。现有控件是 `binding`（一个下拉加自定义框）和 `bindingList`（名字、类型、来源）。
- 下拉选项来自 [frontend/src/ports.ts](../frontend/src/ports.ts) 的 `outputChoices`。它列出其他节点里类型相同的输出，不限制必须是上游；上游限制在运行前由 `node/src/compiler/ports.ts` 的 `checkPortRefs` 完成。
- 新建图的示例在 [frontend/src/store/studioStore.ts](../frontend/src/store/studioStore.ts) 的 `STARTER_GRAPH`：开始 → 提示词 → 大模型 → 结束。

运行时：

- 引用解析和类型检查在 [node/src/compiler/ports.ts](../node/src/compiler/ports.ts)：`readBinding`、`materializeBinding`、`materializeInputList`、`checkPortRefs`、`buildOutputCatalog`。
- 各节点执行器在 [node/src/compiler/nodes.ts](../node/src/compiler/nodes.ts)。`{{input.x}}` 这类替换在 [node/src/compiler/template.ts](../node/src/compiler/template.ts)，未解析的标记变成空串并记一条 warning。
- 图类型枚举在 [contracts/agent-graph.schema.json](../contracts/agent-graph.schema.json)，Java 侧对应 [java/src/main/java/local/agentstack/protocol/NodeType.java](../java/src/main/java/local/agentstack/protocol/NodeType.java)。Java 只校验节点类型在枚举里，不解释端口。

## 目标数据

代码输入和输出节点出参使用同一行结构：

```ts
interface ParamRow {
  name: string;
  type: "string" | "number" | "boolean" | "object";
  description?: string;
  mode: "custom" | "ref";
  value?: unknown;
  /** 形如 `${nodeId}.${field}`，例如 n1.user_input、n3.bodyText */
  ref: string;
}
```

`name` 是 JSON 的 key，必须是标识符，同一张表里不重复。`mode === "ref"` 时 `ref` 指向目录里的一个输出端口，`type` 必须等于该端口的类型。`mode === "custom"` 时用 `value`。输出节点的每一行只有 `ref`。

输出端口在编译期收成目录，沿用现在的 `OutputPort`：`ref`、`nodeId`、`name`、`label`、`type`、`path`。参数值下拉先按节点名称分组，再列出该节点的字段名。

开始的入参行没有 `ref`。它声明的是运行入口：

```ts
interface StartInput {
  name: string;
  type: "string" | "number" | "boolean" | "object";
  description?: string;
  required: boolean;
}
```

大模型的入参行只有名字和引用。提示词不直接写上游字段，只写本表的 `name`：

```ts
interface LlmInput {
  name: string;
  mode: "ref";
  /** 形如 `${nodeId}.${field}`，例如 n1.user_input */
  ref: string;
}
```

固定端口：

| 节点 | 字段 | 类型 | 运行时取值 |
|---|---|---|---|
| 开始 | 每个入参的 `name` | 该行的 type | 运行前用户填写的值，放在 `state.input.<name>` |
| 大模型 | `output` | string | 模型最终文本。写入 `scratchpad[outputKey]`，默认 key 仍是 `answer`，端口 path 为 `scratchpad.answer` |
| 代码 | 出参表里的每个 `name` | 该行的 type | `return` 对象的同名属性。整个返回值仍写入 `scratchpad[outputKey]`，字段 path 为 `scratchpad.<key>.<name>` |
| 输出 | 无端口 | — | 出参表求值后的对象就是本次运行结果 |

提示词模板用单层花括号 `{参数名}`，参数名必须出现在该大模型节点的入参表里。设计图的例子是 `给定一个主题: {topic}, 写一个100字的小故事`，`topic` 是入参名，它的 `ref` 指向开始节点的 `user_input`。现有 `renderTemplate` 识别的是 `{{input.x}}` / `{{scratchpad.y}}`，未解析时替换成空串，继续给旧的提示词节点使用。大模型提示词单独处理：先把入参 materialize 成 `{ [name]: value }`，再替换 `{name}`。名字不在入参表里、值为空、或值不能写成文本时，节点失败。

## 各节点

### 开始

`inputVariables` 改成 `StartInput[]`，控件列是参数名、类型、描述、必填、操作。`outputsOf` 为每一行生成一个端口，`name` 用参数名，path 为 `input.<name>`。设计图的 `user_input` 就是端口 `n1.user_input`。

`createStartRunner` 按这张表读取本次运行入口。必填项缺失时在进图之前失败。用户保存新配置后不再写出旧的 `required` 以外的变量列表形状；打开旧图时见下文「旧图」。

### 代码执行

`inputs` 改为 `ParamRow[]`。运行前 `materializeInputList` 收成 `Record<string, unknown>`，作为 `inputs` 传给 `runJavaScript`。旧的 `name=path` 字符串只在打开旧图时保留，新表单不再写出那种字符串。

新增 `outputs: ParamRow[]` 作为出参声明。`outputsOf` 按这些行生成端口，不再使用单一的 `result` 加 `outputType`。`return` 的值必须是对象，且每个出参名都有值，类型与声明一致；缺字段或类型不对时节点失败。

选开始节点时，下拉先展开该节点，再列出它的入参。用户起的参数名成为 JSON 的 key，值是被选入参的运行时内容。选代码节点时，下拉列出该节点出参表中的字段，不列出一个笼统的「整个返回值」。

代码编辑框保持现在的自定义字符串。提示词的 `{name}` 语法不作用在代码上。

### 大模型

`uiSchema` 按设计图的顺序画四块：

1. `model`：下拉。运行时今天由进程环境 `MODEL_NAME` 决定实际调用的模型（DeepSeek）。节点上保存所选名字，选项用当前进程可用的模型。不在这次接入设计图里的通义百炼。
2. `inputs`：`LlmInput[]`。控件只有参数名、参数值、操作。参数值先是「引用」，再选上游端口。
3. `prompt`：多行文本。用户书写 `{topic}` 这种标记。
4. 出参固定 `[{ name: "output", type: "string" }]`，界面展示参数名、类型、描述，没有加号和参数值。

`system`、`temperature`、`tools`、`maxSteps` 留在配置对象里，避免旧图丢失，但 `uiSchema` 不再把它们画出来。

执行顺序：`materializeBinding` 求出每个入参 → 用入参字典替换 `prompt` 里的 `{name}` → 替换后的文本作为本轮 Human 消息交给模型 → 模型文本写入 `scratchpad.<outputKey>`。输出端口名从现在的 `text` 改为 `output`，path 仍是 `scratchpad.<outputKey>`。

### 输出

配置改为 `params: ParamRow[]`，`uiSchema` 使用下面的参数表控件。`createEndRunner` 对每一行做 `materializeBinding`，得到一个对象，写入 `scratchpad[outputKey]`，并作为本次答案发布。

不再走「没填则采用最后一条模型消息」和「没填则采用 scratchpad 里同名 key」这两条分支。模型文本要出现在结果里，必须在某一行的参数值里引用大模型的 `output`。

单行 string 时，对外答案用该字符串，避免对话里多包一层 JSON。多行时答案是整个对象的 JSON。

### HTTP 与提示词

清单给节点增加 `palette: false`（或等价字段）。[AgentSidebar.tsx](../frontend/src/components/AgentSidebar.tsx) 跳过 `palette === false` 的类型，点击和拖拽都不会添加。`http` 与 `prompt` 都设为不进调色板。

`http` 的执行器、端口和配置保持不动。`prompt` 的执行器也先留着，这样已保存的图还能跑。新示例图 `STARTER_GRAPH` 改为开始 → 大模型 → 输出，prompt 文本写在大模型的 `prompt` 里。

Java `NodeType` 继续保留 `PROMPT` 和 `HTTP`，否则旧图在服务端浅校验会被拒绝。不要从 [contracts/agent-graph.schema.json](../contracts/agent-graph.schema.json) 的 `type` 枚举里删掉这两个值。

## 前端控件

在 [Inspector.tsx](../frontend/src/components/Inspector.tsx) 增加参数表控件，由 `uiSchema` 声明列集合，不按 `node.type` 分支。开始入参、大模型入参、代码输入、代码出参、输出节点出参各用自己的列。参数值控件是分组下拉：第一层是节点名称，第二层是该节点的字段。只收录执行顺序早于当前节点的端口。

每一行：参数名输入、类型选择、描述输入、参数值下拉、上移、下移、删除。表头加号追加一行，默认类型 string、`mode: "custom"`。

参数值下拉的选项调用 `outputChoices`，再按画布顺序去掉自己和更晚的节点。选中一项就写入 `{ mode: "ref", ref, type }`，类型列跟着被选字段改，避免用户选完再改类型造成不一致。改类型时，若当前 `ref` 的类型已经不同，清空 `ref`，回到自定义。

自定义值控件沿用现在 `LiteralInput` 的分型：string、number、boolean、object。

代码节点的出参表没有「参数值」列，只有参数名、类型、描述和排序删除。那张表声明的是自己生产的字段，不是消费别人的字段。

## 运行时校验

`checkPortRefs` 扩展到 `paramTable`：

- `name` 为空、重复、或不是标识符：`INVALID_NODE_CONFIG`。
- `mode === "ref"`：端口必须存在，生产者在当前节点之前，类型等于该行 `type`。规则与现在的 `matchRef` 相同。
- 输出节点和大模型入参的每一行都必须是 `ref`。代码输入允许 `custom`。开始入参没有 `ref`。
- 大模型 `prompt` 里的每个 `{name}` 必须等于本节点某条入参的 `name`。这条入参的 `ref` 再按上面的规则检查端口。名字对不上时在 `planGraph` 里失败，不等到模型调用。

`buildOutputCatalog`：

- 开始按入参行生成端口，path 为 `input.<name>`。
- 大模型端口名改为 `output`。
- 代码按出参行生成多个端口，path 为 `scratchpad.<outputKey>.<name>`。
- HTTP 的现有端口算法不动，仅供旧图。

## 旧图

打开已保存的图时不改写节点配置，除非用户编辑该节点后保存。

| 旧数据 | 打开时 |
|---|---|
| 开始节点的 `inputVariables` | 原样保留并继续按变量列表读入口。列里已有 `name`、`type`、`required`，和新入参表同形的可以照常显示。用户保存后写成 `StartInput[]` |
| 提示词节点 | 节点还在，调色板不能再加。执行器保持现在的行为 |
| HTTP 节点 | 同上 |
| 代码节点的 `inputs` 字符串或旧 binding 行 | `materializeInputList` 继续接受字符串。新参数表保存后是 `ParamRow[]` |
| 代码节点没有出参表 | 目录仍给出一个 `result` 端口，避免旧下游引用断开 |
| 结束节点的单个 `value` | `params` 缺失时走现在的结束逻辑。保存成出参表之后只走新逻辑 |
| 大模型没有 `inputs` / `prompt` | 仍用上游消息和现有的 `system`。界面不展示这些旧字段。新图的提示词写在本节点的 `prompt` 里 |

不在读取时自动把旧图迁移成新结构，避免一次打开就改脏数据。

## 建议改动的文件

实现时按这个顺序，本次文档不改它们：

1. [contracts/node-manifest.json](../contracts/node-manifest.json)：开始、代码、大模型、输出的 schema 和 `uiSchema`；`prompt` 与 `http` 增加不进调色板的标记。然后 `npm run codegen`。
2. [frontend/src/components/Inspector.tsx](../frontend/src/components/Inspector.tsx) 与 [frontend/src/ports.ts](../frontend/src/ports.ts)：分列的参数表，以及按节点分组的字段下拉。
3. [frontend/src/components/AgentSidebar.tsx](../frontend/src/components/AgentSidebar.tsx)：过滤调色板。
4. [frontend/src/store/studioStore.ts](../frontend/src/store/studioStore.ts)：示例图去掉提示词节点。
5. [node/src/compiler/ports.ts](../node/src/compiler/ports.ts)、[node/src/compiler/nodes.ts](../node/src/compiler/nodes.ts)、[node/src/compiler/template.ts](../node/src/compiler/template.ts)：端口目录、参数表求值、`{入参名}` 替换。大模型这条路径解析失败即报错，现有 `{{input.*}}` 替换保持给旧提示词节点使用。
6. 对应测试：`node/test/validate.test.ts`、`node/test/ports` 相关用例、示例图端到端。Java `NodeType` 不用删枚举。

## 验收

- 调色板只有开始、代码执行、大模型、输出。
- 开始节点是入参表。一行 `user_input`（string，必填）时，下游分组下拉展开「开始」能看到 `user_input`。
- 代码输入表选中该字段后，运行时 `inputs.<参数名>` 是用户填写的文本。
- 代码出参表有两个字段时，下游参数值里出现这两个字段，而不是一个整体对象。类型不同的字段不会出现在错误类型的行里。
- 大模型入参 `topic` 引用 `user_input`，提示词含 `{topic}`。运行后模型收到的是替换后的文本。`{topic}` 对不上入参名时该节点失败。
- 大模型出参固定为 `output`。输出节点只有出参表，参数值展开「大模型」选中 `output` 时，运行结果对应该文本。两行时结果是对象。
- 含提示词节点或 HTTP 节点的旧图仍能打开并运行，调色板不能再添加这两种节点。
