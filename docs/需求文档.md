# 节点输入输出需求

画布上的节点改成「输入怎么填、输出给谁用」这一套规则。本文只描述产品行为，不规定实现。

主流程节点是：开始、代码执行、大模型、输出。提示词节点不再提供。HTTP 调用暂时不能新加。

## 节点范围

| 节点 | 这次怎么对待 |
|---|---|
| 开始 | 一张入参表。每一行是工作流启动时要填写的一项，也是下游能选的字段 |
| 代码执行 | 用参数表设计一个 JSON 作为输入；自己也声明出参，供下游按字段选取 |
| 大模型 | 模型、入参、提示词、出参。提示词是模板，用 `{入参名}` 引用本节点的入参 |
| 输出 | 只有出参表。本次运行结果就是这张表 |
| 提示词 | 从产品里去掉。提示词写在大模型节点里，画布不能再添加提示词节点 |
| HTTP 调用 | 调色板不展示，不能新加。已经在图里的节点先留着，不在这次删掉 |

画布仍然是一条线：每个非输出节点一条出边，必须有一个开始和一个输出。

## 参数表

不同节点的表列不一样，对照设计图。

开始的入参：

| 列 | 含义 |
|---|---|
| 参数名 | 启动工作流时这一项的名字，也是下游引用时的字段名 |
| 类型 | string、number、boolean、object 之一 |
| 描述 | 可选说明，告诉填写的人这项是什么 |
| 必填 | 开关。打开时，没填就不能开始这次运行 |
| 操作 | 上移、下移、删除 |

大模型的入参：

| 列 | 含义 |
|---|---|
| 参数名 | 本节点里的名字。提示词用 `{参数名}` 引用它 |
| 参数值 | 先选「引用」，再选上游节点的一个字段 |
| 操作 | 上移、下移、删除 |

输出节点的出参，以及代码执行的输入、出参：

| 列 | 含义 |
|---|---|
| 参数名 | 这一项的名字，作为结果对象或输入 JSON 的 key |
| 描述 | 可选说明，不参与运行 |
| 类型 | string、number、boolean、object 之一 |
| 参数值 | 下拉，按节点分组，选其他节点的一个字段 |
| 操作 | 上移、下移、删除 |

代码执行的出参表没有「参数值」列，因为那些行是自己生产的字段。

表头有加号，用来增加一行。行的顺序就是对象里 key 的顺序。

参数值的下拉按节点分组。展开「大模型」看到 `output`，展开「开始」看到它的入参名，例如 `user_input`。类型对不上的字段不出现。

代码执行的输入行如果没选参数值，可以自己填一个自定义值。自定义值的类型必须和这一行的类型一致：文本用输入框，数字用数字框，布尔用选择，对象用 JSON 文本。开始的入参、大模型的入参、输出节点的出参不使用自定义值：开始由运行时填写，后两者必须引用上游字段。

## 开始

开始节点用入参表声明这次运行要收集的信息。设计图里的一行是：参数名 `user_input`，类型 string，描述「用户输入」，必填打开。

- 可以增加、删除、上移、下移每一行。
- 每一行的参数名在本节点内不重复。
- 下游引用开始节点时，按这些参数名选字段。有一行 `user_input`，下拉里就是「开始」下面的 `user_input`。
- 运行开始前，按这张表向用户收集值。必填行没有值时，这次运行不启动。

## 代码执行

输入是一张参数表。运行前把它收成一个 JSON，交给代码。

选开始节点作为某一行的参数值时：先展开「开始」，再点它的一个入参。类型等于该入参的类型。例如开始有 string 入参 `user_input`，本行参数名是 `topic`，结果是 `{ "topic": "<用户填写的 user_input>" }`。

选代码执行节点的输出作为某一行的参数值时：

- 不能把整个代码节点当成一个值直接塞进来。
- 必须在那个代码节点已经声明的出参里选一个字段。
- 这一行的类型等于被选字段的类型。
- 可以在此之外继续加其他输入行，来源可以是开始、大模型或其他代码节点的某个出参。

代码节点自己也有一张出参表，列与上面相同。下游要引用这段代码时，只能点出参表里的字段。代码 `return` 的对象按出参名取值：出参名是 key，对应值的类型与该行声明一致。

代码本身仍是一段 JavaScript。输入 JSON 在代码里以 `inputs` 使用，例如 `inputs.topic`。

## 大模型

大模型节点包含四块，顺序与设计图一致：模型、入参、提示词、出参。没有单独的提示词节点。

**模型。** 顶部一个模型下拉。图中示例是「通义百炼: 千问系列，默认 Plus」。当前运行时实际调用的是进程里已经配置好的模型；节点上保存所选名字，选项来自当前运行时可用的模型。

**入参。** 一张表，把上游字段收成这个节点自己的参数。设计图里的一行是：参数名 `topic`，参数值「引用」开始节点的 `user_input`。可以继续加行。每一行的参数值必须引用当前节点之前某个节点的一个字段。

**提示词。** 一段模板。用花括号引用本节点入参的参数名，不直接写上游节点的字段名。设计图中的例子：

```text
给定一个主题: {topic}, 写一个100字的小故事
```

`{topic}` 对应入参表里名为 `topic` 的那一行。运行时先求出每个入参的值，再把花括号换成对应文本，然后把整段交给模型。普通文字和换行保留。花括号里的名字必须是本节点入参表里的参数名；对不上、值为空、或该值不能写成文本时，这个节点失败，并指出是哪一个名字。

**出参。** 固定一行：参数名 `output`，类型 string。内容是模型返回的文本。下游在分组下拉里展开「大模型」，选择 `output`。系统提示、工具、温度、最大步数不出现在这个配置里。

## 输出

输出节点（设计图中的「结束」）只有出参表，没有别的输入项。列是参数名、描述、类型、参数值、操作。

设计图里的一行是：参数名 `result`，类型 string，参数值展开「大模型」后选中 `output`。同一下拉里还可以展开「开始」，选它的入参，例如 `user_input`。

- 可以增加、删除、上移、下移每一行。
- 每一行的参数值必须选择其他节点的一个字段，类型与该行一致。
- 要输出模型文本，就在参数值里选择「大模型」下的 `output`。
- 本次运行结果是这张表求值之后的对象：key 是参数名，value 是对应字段的值。图中的一行得到 `{ "result": "<模型返回的文本>" }`。
- 只有一行且类型为 string 时，对话里展示这一行的文本。多行时展示整个对象。

## 引用规则

- 参数值下拉按节点分组，只列出当前节点之前的节点。后面的节点不出现。
- 不能引用自己。
- 开始节点贡献它的入参名。大模型贡献固定字段 `output`。代码节点贡献出参表里的字段。
- 类型必须一致。输出节点的某一行需要 string 时，不能选 number 字段。
- 提示词里的 `{参数名}` 只解析本大模型节点的入参，不解析其他节点的字段名。其他节点的值要先在入参表里引用进来，再在提示词里写对应的参数名。
